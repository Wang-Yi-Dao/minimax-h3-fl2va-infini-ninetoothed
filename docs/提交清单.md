## 三、复现入口（对方拿到工程包后）

工程包根目录下这几条命令即完成「从源码重建 → 装配 → 出片 → 官方 compare」，也就是报告里 **79.493%** 那条重建链的做法：

```bash
# 0) 执行次序确定化（八个 rank 各一条线程，纯异步下发时 rank 间次序不定，会让 50 步轨迹偏移）
export HIP_LAUNCH_BLOCKING=1

# 1) 从源码重建五个 .so（纯 CPU，约 31 分钟；作业时限不够就把 all 拆成 deps / build 两段）
bash build/reproduce.sh $HOME/tmp/repro-build all

# 2) 作业侧装配（装 pylibs、解包库、建模型 symlink；$W 工作区 $AFS 个人存储 $SH 权重目录）
bash jobs/pip_install.sh && python3 -u jobs/setup.py $W $AFS $SH

# 3) 多设备 kernel 缓存键（部署必做，1 分钟，无需重编）
/opt/dtk/llvm/bin/clang -shared -fPIC -O2 -o $W/pre_ctxid.so src/pre_ctxid.c -ldl
export LD_PRELOAD=$W/pre_ctxid.so:$LD_PRELOAD

# 4) 出片 + 官方 compare（参数：步数 预算秒；CRB_LIBS 指向刚重建的库，不设则用包内部署库）
CRB_LIBS=$HOME/tmp/repro-build/ic/build/linux/x86_64/release bash jobs/run_tp8_fl2va.sh 50 2300
```

跨作业等价入口：`jobs/repro_build.sh`（作业A，纯 CPU）+ `jobs/repro_run.sh 50 1500`（作业B，8 卡，自动取链上最新 `libs`）。
