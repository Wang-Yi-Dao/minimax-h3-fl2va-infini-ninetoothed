# 从零复现指令流程（第三方账户版）

面向对象：**在同一算力平台上新建的账户**——有自己的 8 张卡、自己的 $HOME，但看不见我们账户的任何文件与 project。
目标：只靠本仓库 + GitHub Release，从零编译出五个库，跑出 124 帧 768×928 的 FL2VA 成片，并用官方 compare 算出与我们同量级的 SSIM。

**验收基线（2026-11-10 三段链实测；2026-11-13 资产复核）**

| 阶段 | 关键标记 | 实测值 |
|---|---|---|
| 工具链（作业 A） | `XMAKE_TGZ=<size>` | 219 s / 1,753 卡秒，产物 1,666,845 B |
| 构建（作业 B） | `REPRO_OK secs=…` | `secs=1713`，作业 1,841.813 s / 14,735 卡秒 |
| 五个库 | `SO_COUNT=5/5` | 1,612,400 / 30,752,880 / 13,264,224 / 48,184 / 52,104 B |
| 出片（作业 C） | `RUN_RC=0 failed=0` | `run_secs=909`、`18.18 s/step`、mp4 1,615,256 B |
| 官方比对 | `Size:/Length:/Average SSIM:/CMP_RC=` | `PASS (768x928)` / `PASS (124 frames)` / **79.493%** / `0` |

## 第 2 步 作业 A：编工具链（约 4 分钟）

```bash
W=$(for d in /dev/shm/repro-build /tmp/repro-build "$HOME/tmp/repro-build"; do mkdir -p "$d" && touch "$d/.p" && rm -f "$d/.p" && echo "$d" && break; done)
bash build/reproduce.sh "$W" deps
```
判据：`XMAKE_TGZ=<字节数>`、`DEPS_OK`。
也可直接用 Release 的 `prebuilt-libs.tgz` 里的 `xmake-toolchain.tgz` 跳过本步（省 219 s）。

## 第 3 步 作业 B：六步构建（约 30 分钟）

```bash
XM_PREBUILT=<作业A的 tgz> bash build/reproduce.sh "$W" build
```
每 90 s 打 `--- build <行数> <error数> <最后一个 step>`；结尾必须有 `SO_COUNT=5/5` 与 `REPRO_OK secs=… libs=…`。
被时限掐断后同目录续跑：`CRB_RESUME=1 XM_PREBUILT=… bash build/reproduce.sh "$W" build`。
逐条原始命令见文末《附录 A》。

**为什么必须拆三次作业**：单作业硬时限 3,200 s、`TMO` 上限 3,300；构建在 tmpfs 上 1,713 s、出片 909 s，合并必超时。

## 第 5 步 平台提交（批作业，网页操作）

平台网页「批作业」页面即可完成，不需要任何脚本：

1. **项目**：在你自己的账户里新建（或用已有）一个项目，把要跑的 entrypoint 脚本放进项目文件（网页编辑器粘贴，
   或「保存代码版本」上传）。**项目内单文件 ≤ 16 KiB**，超了 403；大 python 拆成一个独立项目文件，由 sh 调用。
2. **配置**：`entrypoint = <脚本名>.sh`、`args` 留空、`kind = batch`。
3. **表单**：资源范围选 `unit`、**卡数填 8**、环境选列表里 `ready=true` 且 `modes` 含 `batch` 的那一条（digest 形如 `524820f2…`）、
   名称随意、**超时 ≤ 3300**。
4. **看结果**：作业卡片 `Queued → Running → Succeeded / Cancelled`；日志在作业详情的日志框里，
   判据就是上面第 2–4 步给出的 `XMAKE_TGZ` / `SO_COUNT=5/5` / `REPRO_OK` / `RUN_RC=0` / `Average SSIM` / `CMP_RC=0`。
5. **报错立刻取消**：作业详情里的取消按钮，不要占着卡排错；取消后到「资源」页面确认空闲卡已恢复。

四条硬规矩：**卡数用 8**（1 卡走临借通道，会报成误导性的 `PROJECT_ENVIRONMENT_CHANGED_OR_UNAVAILABLE`）；
**超时 ≤ 3300**（3600 直接 `403 LEASE_TIME_LIMIT`）；**项目单文件 ≤ 16 KiB**；
**环境列表里没有 `ready=true` 的条目就别提交**（会返回 `PROJECT_NO_COMPATIBLE_CERTIFIED_NODE`，等平台侧恢复，别反复重试）。

## 坑清单

1. 工作目录必须本地盘（`/dev/shm` → `/tmp` → `$HOME/tmp`）；AFS 上编 xmake 15 min+，必超时限。
2. `TMO ≤ 3300`；3. `CNT=8`。
4. 项目文件 ≤ 16 KiB；新文件 `expected_revision=0`。
5. `submit` 不带 `kind`，只有 `preflight` 带。
6. 集群直连 GitHub 常失败：走 `ghproxy.net` / `gh-proxy.com`；被 `$(...)` 捕获的函数里诊断输出必须 `>&2`。
7. `FA_SO_PATH` 缺失时脚本会导出空串，最易触发 `Not load library for Cutlass Fa so`。
8. `wheels/` 与 `wheels5/` 是外部依赖，必须第 0.5 步自己上传。
9. 首帧缺失时脚本打 `FIRST_FRAME_MISSING` 并 `exit 0`，看起来像「成功但没片」。
10. 个人存储只读写自己账户的目录，上传/解包都不需要卡；提交批作业才需要卡。

## 附录 A：六步构建逐条指令

`bash build/reproduce.sh $W build` 就是下面这一串的封装；手敲时按顺序执行，**必须在同一个 shell 里**（环境变量要连续传递）。

| # | 干什么 | 命令 |
|---|---|---|
| 1 | 环境变量 | `export DTK=/opt/dtk ARCH=gfx936 J=32 PY=python3.11 W=/dev/shm/repro-build R=$(pwd)`、`export PYTHON_INCLUDE=$($PY -c 'import sysconfig;print(sysconfig.get_paths()["include"])')`、`mkdir -p $W/{py,ic,xm,tmp,tcache,logs,deps}` |
| 2 | 校验源码输入 | `cd $R/src && sha256sum -c SHA256SUMS && cd -` |
| 3 | 解 InfiniCore 快照 | `tar xzf $R/src/InfiniCore-snapshot-mit.tar.gz -C $W/ic --strip-components=1` |
| 4 | 铺 overlay（9 文件） | 用 python `tarfile` 逐成员写盘（先 `chmod 644`，否则 GNU tar 报 `Cannot open: File exists`）；成功打 `OVL_FILES_WRITTEN 9 failed 0`，再 `grep -c h3_pad80 …/mha_ninetoothed_hygon.cc` |
| 5 | 解 xmake 源码树 | `tar xzf xmake-v3.1.2.tar.gz -C $W/xm` |
| 6 | 编 xmake | `cd $(dirname $(find $W/xm -name configure -perm -u+x | head -1)) && ./configure && make -j$J` |
| 7 | pybind11 3.1.0 | `curl -fL https://ghproxy.net/https://github.com/pybind/pybind11/archive/refs/tags/v3.1.0.tar.gz | tar xz -C $W/deps --strip-components=1` |
| 8 | 取轮子 | `$PY $R/build/fetch_wheels.py $W/whl`（ninetoothed / 海光 triton / numpy） |
| 9 | 解轮子 | `for w in $W/whl/*.whl; do unzip -qo "$w" -d $W/py; done` |
| 10 | thrust 垫片 | 写 `$W/ic/xmake/thrust_shim/thrust/version.h`（`THRUST_VERSION 200400`），并在 `hygon.lua` 的 `local include_dirs = {` 前插 `add_includedirs(shim)` |
| 11 | AOT 补丁 | `$PY $R/build/patch_py.py $W/py` |
| 12 | mkdir 容忍补丁 | `sed -i 's/if not os\._mkdir(_dir) then/if not os._mkdir(_dir) and not os.isdir(_dir) then/' $XM_SHARE/core/base/os.lua` |
| 13 | 关构建缓存 | `sed -i '/^function is_enabled(target)$/a\    do return false end -- P32_CACHE_OFF' $XM_SHARE/modules/private/cache/build_cache.lua` |
| 14 | 九齿 kernel（二选一） | 用现成：`tar xzf $R/src/kernels_deployed.tgz -C $W`；或现场 AOT：`cd $W/ic && $PY -u -c "import infiniop.ops.flash_attention.ninetoothed.build as b; b.build()"`（需 `NINETOOTHED_TARGET=hip:gfx936:64`、`ulimit -s unlimited`、`LD_LIBRARY_PATH=$DTK/llvm/lib`） |
| 15 | dispatcher | `(cd $W/ic && PYTHONPATH=$W/py:$W/ic/src $PY -u $R/build/gen_dispatch.py)` |
| 16 | gfx936 修正 | `sed -i 's/warpSize/64/g; s/cuCtxGetId/hipCtxGetId/g' $W/ic/build/ninetoothed/*.cpp` |
| 17 | configure | `export PATH=$DTK/llvm/bin:$DTK/bin:$PATH XMAKE_ROOT=y XMAKE_GLOBALDIR=$W/xmake-global XMAKE_PROGRAM_DIR=$XM_SHARE INFINI_ROOT=$W/.infini`，再 `$XM_BIN f -y -m release --hygon-dcu=y --hygon-arch=gfx936 --cuda=$DTK/cuda/cuda --aten=y --omp=n --ccl=y --ninetoothed=y --cxflags="-DINFINIOP_HYGON_NINETOOTHED_FLASH_ATTENTION -DTHRUST_IGNORE_CUB_VERSION_CHECK -D__HIP_PLATFORM_AMD__ -Wno-error=unknown-pragmas -Wno-error=unused-result -Wno-error=unused-variable -Wno-error=unused-but-set-variable -Wno-error=unused-function $OMP_INC"` |
| 18 | build | `$XM_BIN -y -j $J`（最慢，约 20 min） |
| 19 | python 绑定 | `mkdir -p $W/.infini/include $W/.infini/lib && cp $W/ic/include/*.h* $W/.infini/include/ && cp $W/ic/build/linux/x86_64/release/*.so $W/.infini/lib/ && $XM_BIN -y -j $J _infinicore`（该 target `set_default(false)`，普通 build 不编） |
| 20 | 核对 | `for f in _infinicore*.so libinfiniop.so libinfinicore_cpp_api.so libinfinirt.so libinfiniccl.so; do printf "%-46s %s\n" $f $(stat -c%s $W/ic/build/linux/x86_64/release/$f); done` |

第 20 条尺寸对得上基线表，才算构建成功——`$W/ic/build/linux/x86_64/release` 就是作业 C 的 `CRB_LIBS`。
