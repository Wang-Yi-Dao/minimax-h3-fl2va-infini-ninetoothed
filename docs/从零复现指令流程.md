# 从零复现指令流程

面向对象：**在同一算力平台上新建的账户**——有独立的 8 张卡与 `$HOME`，但看不到其他账户的文件与 project。
目标：只靠本仓库 + GitHub Release，从零编译出五个库，跑出 124 帧 768×928 的 FL2VA 成片，并用官方 compare 算出同量级的 SSIM。

**验收基线（2026-11-10 三段链实测；2026-11-13 资产复核）**

| 阶段 | 关键标记 | 实测值 |
|---|---|---|
| 工具链（作业 A） | `XMAKE_TGZ=<size>` | 219 s / 1,753 卡秒，产物 1,666,845 B |
| 构建（作业 B） | `REPRO_OK secs=…` | `secs=1713`，作业 1,841.813 s / 14,735 卡秒 |
| 五个库 | `SO_COUNT=5/5` | 1,612,400 / 30,752,880 / 13,264,224 / 48,184 / 52,104 B |
| 出片（作业 C） | `RUN_RC=0 failed=0` | `run_secs=909`、`18.18 s/step`、mp4 1,615,256 B |
| 官方比对 | `Size:/Length:/Average SSIM:/CMP_RC=` | `PASS (768x928)` / `PASS (124 frames)` / **79.493%** / `0` |

## 第 1 步 取代码

```bash
cd $HOME && git clone https://github.com/Wang-Yi-Dao/minimax-h3-fl2va-infini-ninetoothed.git repo && cd repo
ls -l src/      # 四份源码输入
```
`src/` 下应有四份输入：`InfiniCore-snapshot-mit.tar.gz`、`overlay.tar.gz`、`infinicore_ninetoothed_hygon.patch`、`kernels_deployed.tgz`。

### 直连 GitHub 不通怎么办（自行选定）

这条没有唯一答案：**节点能直连就直接 clone；不能直连就自行挑一个镜像，或改用本机网络方案（跳板、代理、预先在本机下载好 tar 包再上传到个人存储）。** 只要 `src/` 里四份输入齐全，代码怎么拿到都不影响结果。

参考（2026-11-13 在平台批作业节点上实测，仅供选型）：直连 `github.com`、`codeload.github.com` 返回 `000`；`gh-proxy.com` 5 s 正常；`ghproxy.net` 偶发 `curl: (92) HTTP/2 stream not closed cleanly`。带重试与 HTTP/1.1 的写法：

```bash
REL=https://github.com/Wang-Yi-Dao/minimax-h3-fl2va-infini-ninetoothed/archive/refs/heads/main.tar.gz
# MIRROR 换成自行选定的镜像前缀；留空就是直连
MIRROR=${MIRROR:-https://gh-proxy.com/}
curl -fL --http1.1 --retry 3 --retry-delay 3 -m 600 -o repo.tgz "$MIRROR$REL" \
  || curl -fL --http1.1 --retry 3 --retry-delay 3 -m 600 -o repo.tgz "https://ghproxy.net/$REL"
tar xzf repo.tgz
```

两条镜像都不通就退回最原始的办法：在本机下载 tar 包，平台「个人存储」上传，节点上再解包——同样合法。

## 第 2 步 作业 A：编工具链

### 先选好工作目录（自行选定）

`reproduce.sh` 的第一个参数是**工作目录**，源码、xmake 源码树、pybind11、九齿 AOT 中间文件、构建产物全放它下面。位置自行选定，只要能写、空间够（建议 ≥10 GB），并且同一个作业/同一条链上沿用同一个路径：

```bash
# 任选其一，替换成实际路径即可：
W=$HOME/mmh3_build                        # 持久盘（作业结束后还在，可续跑）
W=${TMPDIR:-/tmp}/mmh3_build              # 节点内存盘（更快，作业结束即消失）
W=/your/own/writable/dir/mmh3_build       # 自备可写挂载点
mkdir -p "$W" && touch "$W/.p" && rm -f "$W/.p" && echo "WORKDIR=$W"
```

参考（2026-11-13 实测，不是要求）：平台批作业里 `/dev/shm`、`/tmp`、`/var/tmp` 的根目录 `mkdir` 会被拒，能写的是 `$HOME` 与平台给的 `$TMPDIR`（形如 `/dev/shm/infinifabric-preparation/shell-<id>`）。实际环境未必一样，先用上面的 `touch` 探一下再用。

### 编工具链

```bash
bash build/reproduce.sh "$W" deps
```
判据：`XMAKE_TGZ=<字节数>`、`DEPS_OK xmake_prebuilt=<tgz> <字节数> B`。产出的 tgz 默认在 `$W/../.deps/xmake-built.tgz`，用 `XM_OUT=<路径>` 可以指定位置（建议指到持久盘，下一个作业要用）。
也可以跳过本步：Release `assets-v1` 的 `prebuilt-libs.tgz` 里带 `xmake-toolchain.tgz`，解出来直接当 `XM_PREBUILT` 用。

## 第 3 步 作业 B：六步构建

构建有两种跑法，指令不同，按作业时长与机器速度选：

### 跑法一：两段（推荐，作业 A 编好工具链，作业 B 只编 InfiniCore）

```bash
# 作业 A（第 2 步已做）：产出 xmake 工具链 tgz
bash build/reproduce.sh "$W" deps

# 作业 B：拿作业 A 的 tgz 当现成工具链，只跑六步构建
XM_PREBUILT=<作业A产出的 xmake tgz 路径> bash build/reproduce.sh "$W" build
```

### 跑法二：一次性（不拆作业，`all` 把工具链和构建一起做完）

```bash
bash build/reproduce.sh "$W" all
```

两者产出的五个 `.so` 完全一样（同一条构建路径），区别只在「一个作业要跑多久」：

| | 一次性 `all` | 两段 `deps` + `build` |
|---|---|---|
| 作业数 | 1 | 2 |
| 需要 `XM_PREBUILT` | 不需要 | 作业 B 需要（用作业 A 的 tgz） |
| 中途被掐断 | 前面编的工具链一起丢，得从头再来 | 工具链 tgz 已落盘，重跑作业 B 即可 |
| 实测 | 一次性跑完，但**只剩几秒余量**（见下） | 11-10 链上两段跑通 |

2026-11-13 的实测（仅用于估算是否需要拆）：一次性 `all` 整段 2,346 s，作业墙钟 2,395 s，已经贴着平台给的时长；其中「源码编 xmake」一步就占 19 分钟，而机器好的时候这一步只要两分钟。**所以作业时长不宽裕时，用两段。**

### 判据与续跑

每 90 s 打 `--- build <行数> <error数> <最后一个 step>`；结尾必须有 `SO_COUNT=5/5` 与 `REPRO_OK secs=… libs=…`。
被掐断后同目录续跑：`CRB_RESUME=1 XM_PREBUILT=… bash build/reproduce.sh "$W" build`。
逐条原始命令见文末《附录 A》。

## 第 4 步 作业 C：出片 + 官方比对（含分段时长表）

```bash
CRB_LIBS=<作业B的 libs 目录> bash jobs/run_tp8_fl2va_cmpgen.sh 50 1600
```

这一步的生成不由脚本自己发起，而是交给官方 `examples/minimax_h3_compare.py`：它内部的 `run_task()` 起子进程跑
`minimax_h3.py fl2va`（50 步 / seed 42 / 124 帧 / 768×928 / `--gpus=0,…,7`、不带 `--legacy`），把子进程打出的
`[timing]` 行解析成 timings，于是除了 SSIM 还会打印 `[task] completed in …` 和 `[timing comparison]` 分段表。
reference 侧仍然喂现成的 legacy 成片（`--reference-fl2va-video`），不重跑 legacy。

期望（`…` 是随机器波动的数值）：

```
SETUP_EXIT=0 … SETUP_OK
FRESH_LIBS_FROM=<作业B libs>   FRESH libinfiniop.so 30752880 …
FIRST_FRAME=…/input/1280X1280.JPEG
CMP_BUDGET=…s
--- … progress (300s): …s/it
[task] infinilm_fl2va
[task] command: …/minimax_h3.py fl2va --model-path=… --text=A dog falls asleep --gpus=0,1,2,3,4,5,6,7 --steps=50 --seed=42 --num-frames=124 --output=…/cmpout/infinilm_fl2va.mp4 --first-frame=…/1280X1280.JPEG
  model.transformer_create_and_load            … s
  compute.h3_transformer                       … s
[task] completed in … s: …/cmpout/infinilm_fl2va.mp4
[timing comparison] fl2va
  component                                    reference    infinilm    speedup
  compute.h3_transformer                       n/a          … s        n/a
[result] MiniMax-H3 video comparison
  fl2va: PASS (768x928, 124 frames)
    Average SSIM: …%
GET_MP4 bytes=… path=$HOME/output2/cmpgen_<时间戳>.mp4
CMP_RC=0 failed=0 cmp_secs=…

```

表里 reference 侧一律 `n/a`（legacy 侧用已有成片，没有重新计时）。同一套生成参数在重建链上实测过：
`RUN_RC=0 failed=0 run_secs=909 steps=50 sec_per_step=18.18`、`Average SSIM: 79.493%`、`CMP_RC=0`；
那份成片由 `jobs/run_tp8_fl2va.sh` 出、再喂给 compare 的 `--infinilm-fl2va-video`，所以只有 SSIM 没有时长表。

判据：`CMP_RC=0`、`Size`/`Length` 两个 PASS、SSIM 与 79.493% 同量级、日志里出现 `[timing comparison] fl2va`。
出片后成片发布在 `$HOME/output2/cmpgen_<时间戳>.mp4`；日志在 `$HOME/logs/cmpgen_<时间戳>.log`。

## 第 5 步 平台提交（批作业，网页操作）

平台网页「批作业」页面即可完成，不需要任何脚本：

1. **项目**：在平台账户下新建（或用已有）一个项目，把要跑的 entrypoint 脚本放进项目文件（网页编辑器粘贴，
   或「保存代码版本」上传）。**项目内单文件 ≤ 16 KiB**，超了 403；大 python 拆成一个独立项目文件，由 sh 调用。
2. **配置**：`entrypoint = <脚本名>.sh`、`args` 留空、`kind = batch`。
3. **表单**：资源范围选 `unit`；**卡数与超时按账户此刻能拿到的填**（页面上的 preflight 会显示哪些卡数 `allowed`、
   哪些环境 `ready=true` 且 `modes` 含 `batch`）；名称随意。
4. **看结果**：作业卡片 `Queued → Running → Succeeded / Cancelled`；日志在作业详情的日志框里，
   判据就是上面第 2–4 步给出的 `XMAKE_TGZ` / `SO_COUNT=5/5` / `REPRO_OK` / `RUN_RC=0` / `Average SSIM` / `CMP_RC=0`。
5. **报错立刻取消**：作业详情里的取消按钮，不要占着卡排错；取消后到「资源」页面确认空闲卡已恢复。

三条硬规矩：**卡数别选到「走临借通道」的那一档**（会报成误导性的 `PROJECT_ENVIRONMENT_CHANGED_OR_UNAVAILABLE`，看不出真实原因）；
**项目单文件 ≤ 16 KiB**（超了 403，大 python 拆成独立项目文件由 sh 调用）；
**环境列表里没有 `ready=true` 的条目就别提交**（会返回 `PROJECT_NO_COMPATIBLE_CERTIFIED_NODE`，等平台侧恢复，别反复重试）。

## 坑清单

1. **工作目录自行选定**：编 xmake 那一步对磁盘 IO 极敏感，网络盘/共享盘上可能慢十倍（实测过 15 分钟以上）；内存盘或本地盘最快。选目录前先 `touch` 探一下写权限（见第 2 步）。
2. 卡数与超时按页面 preflight 给的允许值填，不要照抄其他环境的值。
3. 项目文件 ≤ 16 KiB；新建项目文件要走 `expected_revision=0`。
4. `submit` 不带 `kind`，只有 `preflight` 带（`batch.js` 里就是这么发的）。
5. 节点直连 GitHub 常失败，镜像自己挑（`gh-proxy.com` / `ghproxy.net` / 自建跳板）；被 `$(...)` 捕获的函数里诊断输出必须 `>&2`。
6. `FA_SO_PATH` 缺失时脚本会导出空串，最易触发 `Not load library for Cutlass Fa so`。
7. `wheels/` 与 `wheels5/` 是外部依赖，必须第 0.5 步自己上传。
8. `artifacts/{infinicore,infinilm}.tgz` 不在 `$HOME/minimax_h3/artifacts/` 时，作业 C 直接 `SETUP_FAIL tars` 退出 21。
9. 首帧缺失时脚本打 `FIRST_FRAME_MISSING` 并 `exit 0`，看起来像「成功但没片」。
10. 个人存储只读写自己账户的目录，上传/解包都不需要卡；提交批作业才需要卡。

## 附录 A：六步构建逐条指令

`bash build/reproduce.sh $W build` 就是下面这一串的封装；手敲时按顺序执行，**必须在同一个 shell 里**（环境变量要连续传递）。

| # | 干什么 | 命令 |
|---|---|---|
| 1 | 环境变量 | `export DTK=/opt/dtk ARCH=gfx936 J=32 PY=python3.11 W=<工作目录> R=$(pwd)`、`export PYTHON_INCLUDE=$($PY -c 'import sysconfig;print(sysconfig.get_paths()["include"])')`、`mkdir -p $W/{py,ic,xm,tmp,tcache,logs,deps}` |
| 2 | 解 InfiniCore 快照 | `tar xzf $R/src/InfiniCore-snapshot-mit.tar.gz -C $W/ic --strip-components=1` |
| 3 | 铺 overlay（9 文件） | 用 python `tarfile` 逐成员写盘（先 `chmod 644`，否则 GNU tar 报 `Cannot open: File exists`）；成功打 `OVL_FILES_WRITTEN 9 failed 0`，再 `grep -c h3_pad80 …/mha_ninetoothed_hygon.cc` |
| 4 | 解 xmake 源码树 | `tar xzf xmake-v3.1.2.tar.gz -C $W/xm` |
| 5 | 编 xmake | `cd $(dirname $(find $W/xm -name configure -perm -u+x | head -1)) && ./configure && make -j$J` |
| 6 | pybind11 3.1.0 | `curl -fL https://ghproxy.net/https://github.com/pybind/pybind11/archive/refs/tags/v3.1.0.tar.gz | tar xz -C $W/deps --strip-components=1` |
| 7 | 取轮子 | `$PY $R/build/fetch_wheels.py $W/whl`（ninetoothed / 海光 triton / numpy） |
| 8 | 解轮子 | `for w in $W/whl/*.whl; do unzip -qo "$w" -d $W/py; done` |
| 9 | thrust 垫片 | 写 `$W/ic/xmake/thrust_shim/thrust/version.h`（`THRUST_VERSION 200400`），并在 `hygon.lua` 的 `local include_dirs = {` 前插 `add_includedirs(shim)` |
| 10 | AOT 补丁 | `$PY $R/build/patch_py.py $W/py` |
