# 从零复现指令流程（第三方账户版）

面向对象：**在同一算力平台上新建的账户**——有自己的 8 张卡、自己的 $HOME，但看不见我们账户的任何文件与 project。
目标：只靠本仓库 + GitHub Release，从零编译出五个库，跑出 124 帧 768×928 的 FL2VA 成片，并用官方 compare 算出与我们同量级的 SSIM。

**验收基线（2026-11-10 三段链实测；2026-11-13 资产复核）**

| 阶段 | 关键标记 | 实测值 |
|---|---|---|
| 工具链（作业 A） | `XMAKE_TGZ=<size>` | 219 s / 1,753 卡秒，产物 1,666,845 B |
| 构建（作业 B） | `REPRO_OK secs=…` | `secs=1713`，作业 1,841.813 s / 14,735 卡秒 |
| 五个库 | `SO_COUNT=5/5` | 1,612,400 / 30,752,880 / 13,264,224 / 48,184 / 52,104 B |
| 出片（作业 C） | `RUN_RC=0 failed=0` | `run_secs=909`、`18.18 s/step`、mp4 1,615,256 B |
| 官方比对 | `Size:/Length:/Average SSIM:/CMP_RC=` | `PASS (768x928)` / `PASS (124 frames)` / **79.493%** / `0` |

## 第 1 步 取代码 + 校验源码输入

```bash
cd $HOME && git clone https://github.com/Wang-Yi-Dao/minimax-h3-fl2va-infini-ninetoothed.git repo && cd repo

```
期望四行 `OK`：`InfiniCore-snapshot-mit.tar.gz` 3,759,864 / `overlay.tar.gz` 19,254 / `infinicore_ninetoothed_hygon.patch` 52,648 / `kernels_deployed.tgz` 2,457,374。

### 直连 GitHub 不通怎么办（由你决定）

这条没有唯一答案：**节点能直连就直接 clone；不能直连就自己挑一个镜像，或用你自己的网络方案（跳板、代理、预先在自己机器上下载好 tar 包再上传到个人存储）。** 只要 `src/SHA256SUMS` 四行校验通过，代码怎么拿到都不影响结果。

参考（2026-11-13 在平台批作业节点上实测，仅供选型）：直连 `github.com`、`codeload.github.com` 返回 `000`；`gh-proxy.com` 5 s 正常；`ghproxy.net` 偶发 `curl: (92) HTTP/2 stream not closed cleanly`。带重试与 HTTP/1.1 的写法：

```bash
REL=https://github.com/Wang-Yi-Dao/minimax-h3-fl2va-infini-ninetoothed/archive/refs/heads/main.tar.gz
# MIRROR 换成你自己选的镜像前缀；留空就是直连
MIRROR=${MIRROR:-https://gh-proxy.com/}
curl -fL --http1.1 --retry 3 --retry-delay 3 -m 600 -o repo.tgz "$MIRROR$REL" \
  || curl -fL --http1.1 --retry 3 --retry-delay 3 -m 600 -o repo.tgz "https://ghproxy.net/$REL"
tar xzf repo.tgz
```

两条镜像都不通就退回最原始的办法：在自己机器上下载 tar 包，平台「个人存储」上传，节点上再解包——同样合法。

## 第 2 步 作业 A：编工具链

### 先选好工作目录（由你决定）

`reproduce.sh` 的第一个参数是**工作目录**，源码、xmake 源码树、pybind11、九齿 AOT 中间文件、构建产物全放它下面。位置由你挑，只要能写、空间够（建议 ≥10 GB），并且同一个作业/同一条链上沿用同一个路径：

```bash
# 任选其一，替换成你自己的路径即可：
W=$HOME/mmh3_build                        # 持久盘（作业结束后还在，可续跑）
W=${TMPDIR:-/tmp}/mmh3_build              # 节点内存盘（更快，作业结束即消失）
W=/your/own/writable/dir/mmh3_build       # 你自己的挂载点
mkdir -p "$W" && touch "$W/.p" && rm -f "$W/.p" && echo "WORKDIR=$W"
```

参考（2026-11-13 实测，不是要求）：平台批作业里 `/dev/shm`、`/tmp`、`/var/tmp` 的根目录 `mkdir` 会被拒，能写的是 `$HOME` 与平台给的 `$TMPDIR`（形如 `/dev/shm/infinifabric-preparation/shell-<id>`）。你自己的环境未必一样，先用上面的 `touch` 探一下再用。

### 编工具链

```bash
bash build/reproduce.sh "$W" deps
```
判据：`XMAKE_TGZ=<字节数>`、`DEPS_OK xmake_prebuilt=<tgz> <字节数> B`。产出的 tgz 默认在 `$W/../.deps/xmake-built.tgz`，用 `XM_OUT=<路径>` 可以指定位置（建议指到持久盘，下一个作业要用）。
也可以跳过本步：Release `assets-v1` 的 `prebuilt-libs.tgz` 里带 `xmake-toolchain.tgz`，解出来直接当 `XM_PREBUILT` 用。

## 第 3 步 作业 B：六步构建

构建有两种跑法，指令不同，按你自己的作业时长/机器速度选：

### 跑法一：两段（推荐，作业 A 编好工具链，作业 B 只编 InfiniCore）

```bash
# 作业 A（第 2 步已做）：产出 xmake 工具链 tgz
bash build/reproduce.sh "$W" deps

# 作业 B：拿作业 A 的 tgz 当现成工具链，只跑六步构建
XM_PREBUILT=<作业A产出的 xmake tgz 路径> bash build/reproduce.sh "$W" build
```

### 跑法二：一次性（不拆作业，`all` 把工具链和构建一起做完）

```bash
bash build/reproduce.sh "$W" all
```

两者产出的五个 `.so` 完全一样（同一条构建路径），区别只在「一个作业要跑多久」：

| | 一次性 `all` | 两段 `deps` + `build` |
|---|---|---|
| 作业数 | 1 | 2 |
| 需要 `XM_PREBUILT` | 不需要 | 作业 B 需要（用作业 A 的 tgz） |
| 中途被掐断 | 前面编的工具链一起丢，得从头再来 | 工具链 tgz 已落盘，重跑作业 B 即可 |
| 我们实测 | 一次性跑完，但**只剩几秒余量**（见下） | 11-10 链上两段跑通 |

我们 2026-11-13 的实测（仅供你估自己要不要拆）：一次性 `all` 整段 2,346 s，作业墙钟 2,395 s，已经贴着平台给的时长；其中「源码编 xmake」一步就占 19 分钟，而机器好的时候这一步只要两分钟。**所以只要你拿到的作业时长不宽裕，就用两段。**

### 判据与续跑

每 90 s 打 `--- build <行数> <error数> <最后一个 step>`；结尾必须有 `SO_COUNT=5/5` 与 `REPRO_OK secs=… libs=…`。
被掐断后同目录续跑：`CRB_RESUME=1 XM_PREBUILT=… bash build/reproduce.sh "$W" build`。
逐条原始命令见文末《附录 A》。

## 第 5 步 平台提交（批作业，网页操作）

平台网页「批作业」页面即可完成，不需要任何脚本：

1. **项目**：在你自己的账户里新建（或用已有）一个项目，把要跑的 entrypoint 脚本放进项目文件（网页编辑器粘贴，
   或「保存代码版本」上传）。**项目内单文件 ≤ 16 KiB**，超了 403；大 python 拆成一个独立项目文件，由 sh 调用。
2. **配置**：`entrypoint = <脚本名>.sh`、`args` 留空、`kind = batch`。
3. **表单**：资源范围选 `unit`；**卡数与超时按你账户此刻能拿到的填**（页面上的 preflight 会告诉你哪些卡数 `allowed`、
   哪些环境 `ready=true` 且 `modes` 含 `batch`）；名称随意。
4. **看结果**：作业卡片 `Queued → Running → Succeeded / Cancelled`；日志在作业详情的日志框里，
   判据就是上面第 2–4 步给出的 `XMAKE_TGZ` / `SO_COUNT=5/5` / `REPRO_OK` / `RUN_RC=0` / `Average SSIM` / `CMP_RC=0`。
5. **报错立刻取消**：作业详情里的取消按钮，不要占着卡排错；取消后到「资源」页面确认空闲卡已恢复。

三条硬规矩：**卡数别选到「走临借通道」的那一档**（会报成误导性的 `PROJECT_ENVIRONMENT_CHANGED_OR_UNAVAILABLE`，看不出真实原因）；
**项目单文件 ≤ 16 KiB**（超了 403，大 python 拆成独立项目文件由 sh 调用）；
**环境列表里没有 `ready=true` 的条目就别提交**（会返回 `PROJECT_NO_COMPATIBLE_CERTIFIED_NODE`，等平台侧恢复，别反复重试）。

## 坑清单

1. **工作目录自己挑**：编 xmake 那一步对磁盘 IO 极敏感，网络盘/共享盘上可能慢十倍（我们实测过 15 分钟以上）；内存盘或本地盘最快。选目录前先 `touch` 探一下写权限（见第 2 步）。
2. 卡数与超时按页面 preflight 给的允许值填，别硬抄别人的数。
3. 项目文件 ≤ 16 KiB；新建项目文件要走 `expected_revision=0`。
4. `submit` 不带 `kind`，只有 `preflight` 带（`batch.js` 里就是这么发的）。
5. 节点直连 GitHub 常失败，镜像自己挑（`gh-proxy.com` / `ghproxy.net` / 自建跳板）；被 `$(...)` 捕获的函数里诊断输出必须 `>&2`。
6. `FA_SO_PATH` 缺失时脚本会导出空串，最易触发 `Not load library for Cutlass Fa so`。
7. `wheels/` 与 `wheels5/` 是外部依赖，必须第 0.5 步自己上传。
8. `artifacts/{infinicore,infinilm}.tgz` 不在 `$HOME/minimax_h3/artifacts/` 时，作业 C 直接 `SETUP_FAIL tars` 退出 21。
9. 首帧缺失时脚本打 `FIRST_FRAME_MISSING` 并 `exit 0`，看起来像「成功但没片」。
10. 个人存储只读写自己账户的目录，上传/解包都不需要卡；提交批作业才需要卡。

## 附录 A：六步构建逐条指令

`bash build/reproduce.sh $W build` 就是下面这一串的封装；手敲时按顺序执行，**必须在同一个 shell 里**（环境变量要连续传递）。

| # | 干什么 | 命令 |
|---|---|---|
| 1 | 环境变量 | `export DTK=/opt/dtk ARCH=gfx936 J=32 PY=python3.11 W=<你的工作目录> R=$(pwd)`、`export PYTHON_INCLUDE=$($PY -c 'import sysconfig;print(sysconfig.get_paths()["include"])')`、`mkdir -p $W/{py,ic,xm,tmp,tcache,logs,deps}` |
| 2 | 校验源码输入 | `cd $R/src && sha256sum -c SHA256SUMS && cd -` |
| 3 | 解 InfiniCore 快照 | `tar xzf $R/src/InfiniCore-snapshot-mit.tar.gz -C $W/ic --strip-components=1` |
| 4 | 铺 overlay（9 文件） | 用 python `tarfile` 逐成员写盘（先 `chmod 644`，否则 GNU tar 报 `Cannot open: File exists`）；成功打 `OVL_FILES_WRITTEN 9 failed 0`，再 `grep -c h3_pad80 …/mha_ninetoothed_hygon.cc` |
| 5 | 解 xmake 源码树 | `tar xzf xmake-v3.1.2.tar.gz -C $W/xm` |
| 6 | 编 xmake | `cd $(dirname $(find $W/xm -name configure -perm -u+x | head -1)) && ./configure && make -j$J` |
| 7 | pybind11 3.1.0 | `curl -fL https://ghproxy.net/https://github.com/pybind/pybind11/archive/refs/tags/v3.1.0.tar.gz | tar xz -C $W/deps --strip-components=1` |
| 8 | 取轮子 | `$PY $R/build/fetch_wheels.py $W/whl`（ninetoothed / 海光 triton / numpy） |
| 9 | 解轮子 | `for w in $W/whl/*.whl; do unzip -qo "$w" -d $W/py; done` |
| 10 | thrust 垫片 | 写 `$W/ic/xmake/thrust_shim/thrust/version.h`（`THRUST_VERSION 200400`），并在 `hygon.lua` 的 `local include_dirs = {` 前插 `add_includedirs(shim)` |
| 11 | AOT 补丁 | `$PY $R/build/patch_py.py $W/py` |
| 12 | mkdir 容忍补丁 | `sed -i 's/if not os\._mkdir(_dir) then/if not os._mkdir(_dir) and not os.isdir(_dir) then/' $XM_SHARE/core/base/os.lua` |
| 13 | 关构建缓存 | `sed -i '/^function is_enabled(target)$/a\    do return false end -- P32_CACHE_OFF' $XM_SHARE/modules/private/cache/build_cache.lua` |
| 14 | 九齿 kernel（二选一） | 用现成：`tar xzf $R/src/kernels_deployed.tgz -C $W`；或现场 AOT：`cd $W/ic && $PY -u -c "import infiniop.ops.flash_attention.ninetoothed.build as b; b.build()"`（需 `NINETOOTHED_TARGET=hip:gfx936:64`、`ulimit -s unlimited`、`LD_LIBRARY_PATH=$DTK/llvm/lib`） |
| 15 | dispatcher | `(cd $W/ic && PYTHONPATH=$W/py:$W/ic/src $PY -u $R/build/gen_dispatch.py)` |
| 16 | gfx936 修正 | `sed -i 's/warpSize/64/g; s/cuCtxGetId/hipCtxGetId/g' $W/ic/build/ninetoothed/*.cpp` |
| 17 | configure | `export PATH=$DTK/llvm/bin:$DTK/bin:$PATH XMAKE_ROOT=y XMAKE_GLOBALDIR=$W/xmake-global XMAKE_PROGRAM_DIR=$XM_SHARE INFINI_ROOT=$W/.infini`，再 `$XM_BIN f -y -m release --hygon-dcu=y --hygon-arch=gfx936 --cuda=$DTK/cuda/cuda --aten=y --omp=n --ccl=y --ninetoothed=y --cxflags="-DINFINIOP_HYGON_NINETOOTHED_FLASH_ATTENTION -DTHRUST_IGNORE_CUB_VERSION_CHECK -D__HIP_PLATFORM_AMD__ -Wno-error=unknown-pragmas -Wno-error=unused-result -Wno-error=unused-variable -Wno-error=unused-but-set-variable -Wno-error=unused-function $OMP_INC"` |
